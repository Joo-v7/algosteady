# 아키텍처

## 전체 구성

```text
React 화면
    │ /api
    ▼
Spring Boot ───────────── PostgreSQL
    │ 실행·채점 작업           콘텐츠·제출·작업·결과
    ▼
단일 작업자 → 언어별 Docker 실행 환경
                 준비·컴파일 → 테스트 실행 → 결과 수집·정리
```

프론트엔드는 입력·화면 표시·작업 상태 조회를 담당한다. 백엔드는 콘텐츠와 제출을 관리하고 실행 결과를 저장한다.

## 프로젝트 구성

| 디렉터리 | 역할 |
| --- | --- |
| `frontend/` | React 페이지, API 호출·타입, 스타일 |
| `backend/` | 콘텐츠·제출·채점 API 및 실행부 |
| `content/` | 과제 설명, 언어별 코드·테스트 |
| `runners/` | 언어별 Docker 이미지 정의 |
| `docs/` | API, 구조, 콘텐츠 규격 |

## 백엔드 모듈

| 모듈 | 역할 |
| --- | --- |
| `exercise` | 콘텐츠 검증·등록, 목록·상세·기준 코드 조회 |
| `training` | 제출 원본 저장, 제출 기록 조회 |
| `judging` | 작업 상태 관리, 기대값 비교, 결과 저장·집계 |
| `judging.runner` | 언어별 준비·실행, 출력 수집, 제한·자원 정리 |
| `common` | 공통 오류 응답 |

의존 방향은 `training → judging → exercise`다. Controller는 HTTP, Service는 업무 처리·트랜잭션, Repository는 DB 접근을 담당한다. runner는 DB나 채점 기준을 참조하지 않는다.

## 실행·저장 흐름

1. 과제 파일을 검증해 버전별 콘텐츠로 등록한다.
2. 실행 요청을 작업으로 저장한다. 전체 채점은 제출 원본도 같은 트랜잭션으로 저장한다.
3. 단일 작업자가 대기 작업을 가져와 실행한다. 실제 실행 동안 DB 트랜잭션을 유지하지 않는다.
4. 테스트별 결과를 저장하고, 화면은 작업 조회 API로 진행·결과를 표시한다.
5. 제출 기록은 원본과 연결된 작업 결과를 함께 조회한다.

콘텐츠·제출 원본은 보존하고, 채점 상태·결과는 judging에서 관리한다. 초안은 브라우저에 저장한다. DB 구조는 Flyway로 관리한다.

## 실행 환경

언어별 Docker 이미지와 준비·실행 명령을 선택하고, 나머지 작업 처리 흐름은 공유한다. 초기 지원 언어는 C17이며 Java·Python·C++로 확장한다.

- 작업마다 독립된 컨테이너에서 준비·컴파일하고 테스트마다 새 프로세스로 실행한다.
- 네트워크·권한·CPU·메모리·프로세스 수·실행 시간·출력량을 제한한다.
- 출력·오류·종료 코드·실행 시간을 수집하고 완료·실패 시 컨테이너와 임시 파일을 정리한다.
- 서버 재시작 시 실행 중이던 작업은 중단으로 기록하고 대기 작업은 이어서 처리한다.

실행 제한과 이미지 이름은 [설정 파일](../backend/src/main/resources/application.properties), 실행 명령은 `LanguageSpec`에서 관리한다. 로컬 실행법은 [README](../README.md#로컬-실행)를 참고한다.
