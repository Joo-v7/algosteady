# 아키텍처

## 전체 구성

```text
React 화면
    │ /api
    ▼
Spring Boot ───────────── PostgreSQL
    │ 실행·채점 작업           콘텐츠·제출·작업·결과
    ▼
단일 작업자 → 언어별 Docker 실행 환경
                 준비·컴파일 → 테스트 실행 → 결과 수집·정리
```

프론트엔드는 입력·화면 표시·작업 상태 조회를 담당한다. 백엔드는 콘텐츠와 제출을 관리하고 실행 결과를 저장한다.

## 프로젝트 구성

| 디렉터리 | 역할 |
| --- | --- |
| `frontend/` | React 페이지, API 호출·타입, 스타일 |
| `backend/` | 콘텐츠·제출·채점 API 및 실행부 |
| `content/` | 과제 설명, 언어별 코드·테스트 |
| `runners/` | 언어별 Docker 이미지 정의 |
| `docs/` | API, 구조, 콘텐츠 규격 |

## 백엔드 모듈

| 모듈 | 역할 |
| --- | --- |
| `exercise` | 콘텐츠 검증·등록, 목록·상세·기준 코드 조회 |
| `training` | 제출 원본 저장, 제출 기록 조회 |
| `judging` | 작업 상태 관리, 기대값 비교, 결과 저장·집계 |
| `judging.runner` | 언어별 준비·실행, 출력 수집, 제한·자원 정리 |
| `common` | 공통 오류 응답 |

의존 방향은 `training → judging → exercise`다. Controller는 HTTP, Service는 업무 처리·트랜잭션, Repository는 DB 접근을 담당한다. runner는 DB나 채점 기준을 참조하지 않는다.

## 실행·저장 흐름

1. 과제 파일을 검증해 버전별 콘텐츠로 등록한다.
2. 실행 요청을 작업으로 저장한다. 전체 채점은 제출 원본도 같은 트랜잭션으로 저장한다.
3. 단일 작업자가 대기 작업을 가져와 실행한다. 실제 실행 동안 DB 트랜잭션을 유지하지 않는다.
4. 테스트별 결과를 저장하고, 화면은 작업 조회 API로 진행·결과를 표시한다.
5. 제출 기록은 원본과 연결된 작업 결과를 함께 조회한다.

콘텐츠·제출 원본은 보존하고, 채점 상태·결과는 judging에서 관리한다. 초안은 브라우저에 저장한다. DB 구조는 Flyway로 관리한다.

## 실행 환경

언어별 Docker 이미지와 준비·실행 명령을 선택하고, 나머지 작업 처리 흐름은 공유한다. 초기 지원 언어는 C17이며 Java·Python·C++로 확장한다.

- 작업마다 독립된 컨테이너에서 준비·컴파일하고 테스트마다 새 프로세스로 실행한다.
- 네트워크·권한·CPU·메모리·프로세스 수·실행 시간·출력량을 제한한다.
- 출력·오류·종료 코드·실행 시간을 수집하고 완료·실패 시 컨테이너와 임시 파일을 정리한다.
- 서버 재시작 시 실행 중이던 작업은 중단으로 기록하고 대기 작업은 이어서 처리한다.

실행 제한과 이미지 이름은 [설정 파일](../backend/src/main/resources/application.properties), 실행 명령은 `LanguageSpec`에서 관리한다. 로컬 실행법은 [README](../README.md#로컬-실행)를 참고한다.

## 추가 기능·화면 계획

**추가일: 2026-10-25 · 홈 개편 구현, 로그인·개인 기록 구현 예정**

하루에 하나의 자료구조·알고리즘을 직접 작성하고 전체 채점을 통과하는 흐름을 추가한다. 기존 학습·실습·실행·제출 기능에 로그인과 개인 기록을 연결한다.

### 로그인·개인 기록

- Spring Security와 Google OAuth로 로그인한다. 별도 회원가입 화면과 비밀번호 로그인은 제공하지 않는다.
- 상단 메뉴는 비로그인 시 `홈 · 로그인`, 로그인 시 `홈 · 마이페이지 · 로그아웃`으로 구성한다.
- `로그인`을 누르면 별도 로그인 화면에서 `Google로 계속하기`를 제공한다. 로그인 수단을 추가해도 상단 메뉴 이름은 유지한다.
- 제출·실행 작업을 회원에게 연결하고, 본인 코드와 기록만 조회하도록 서버에서 확인한다.

### 홈

| 영역 | 구성 |
| --- | --- |
| 오늘의 학습 | 로그인 여부와 관계없이 같은 추천을 표시한다. 한국 시간 오전 6시를 하루의 시작으로 사용하고 홈 진입 시 기준 날짜를 계산한다. 같은 날짜와 같은 목록에서는 추천을 유지한다. |
| 오늘의 학습 카드 | 기존 학습 카드의 제목·설명·태그·학습·실습 버튼을 사용해 가로로 넓게 표시한다. 기존 학습·실습 화면으로 이동하며 완료 상태 표시는 회원 기능에서 추가한다. |
| 학습 목록 | 오늘의 학습 아래에 분류 드롭다운·이름 검색창·돋보기 아이콘이 있는 조회 버튼을 배치한다. 분류 이름·순서·소속 관계는 DB에서 관리하고 분류 API로 조회한다. |
| 검색 결과 | 선택·입력 중에는 목록을 유지하고 조회 버튼 또는 Enter로 조건을 적용하며 첫 페이지로 이동한다. 페이지당 최대 9개를 데스크톱 3열·태블릿 2열·모바일 1열로 표시한다. 오늘의 학습은 검색과 별도로 유지한다. |
| 페이지 이동 | 처음·이전·페이지 번호·다음·마지막 버튼을 제공한다. 번호는 데스크톱 최대 5개, 모바일 최대 3개를 표시하고 분류·검색어·페이지를 URL에 보존한다. |

`오늘의 학습`·`학습 목록` 제목과 검색 영역은 가운데 정렬하고 카드 내부 내용은 왼쪽 정렬한다. 추천은 기존 목록과 기준 날짜로 프론트에서 계산하며 별도 저장·API를 추가하지 않는다.

### 마이페이지

프로필 사진과 제출 기록 표는 배치하지 않고, 영역 제목을 가운데 정렬한다.

| 영역 | 구성 |
| --- | --- |
| 학습 현황 | 현재 연속 완료 일수, 누적 완료 일수, 전체 학습 중 완료한 항목 수를 표시한다. |
| 학습 기록 | 연도를 선택하고 GitHub 잔디처럼 날짜별 작은 칸으로 완료한 날을 표시한다. 하루 완료 여부에 따라 한 가지 색을 사용한다. |
| 기록 이동 | 날짜를 누르면 그날의 본인 제출 기록 화면으로 이동한다. 실패·통과 시도와 제출 코드 상세를 확인하며, 전체 제출 기록 링크도 제공한다. |
| 회원탈퇴 | 학습 기록 카드 바깥, 페이지 맨 아래 오른쪽에 작은 텍스트 버튼으로 배치한다. 데이터 처리 안내와 탈퇴 확인을 거친다. |

- 오늘 배정된 학습의 **전체 채점 기준을 통과한 날만** 잔디와 완료 일수에 반영한다. 단순 제출·예제 실행·기준 코드 열람으로는 인정하지 않는다.
- 같은 날 여러 번 통과해도 하루 완료는 한 번만 인정한다. 다른 학습을 통과한 기록은 별도로 보존한다.
- 완료한 학습 항목 수는 오늘의 배정 여부와 관계없이 전체 채점을 통과한 서로 다른 항목 수다.

### 관리자·콘텐츠 관리

**기준 정리: 2026-10-28 · 관리자 기능 구현 예정**

- 분류 이름·표시 순서·소속 관계는 기존 분류 테이블을 관리자에서 편집한다.
- 제목·설명·학습 내용과 언어별 코드·테스트는 과제 콘텐츠로 편집하고, 검증 후 새 버전으로 발행한다. 기존 제출이 참조하는 버전은 보존한다.
- 화면 배치·시각화 방식은 React 코드에서 관리한다. 시각화 데이터와 학습 문구의 관리 경계는 [콘텐츠 관리 기준](content.md#관리-기준)을 따른다.

관리자 편집·발행 기능은 기존 DB·버전별 스냅샷 구조를 바탕으로 구현한다.

### 구현 전 확인할 정책

- 비로그인 사용자의 실행·제출 허용 여부
- 기존 비회원 제출 기록의 계정 연결 방식
- 잔디의 완료 날짜 집계 기준과 날짜별 제출 기록 조회 범위
- 회원탈퇴 시 계정·제출·학습 기록의 삭제 또는 보존 범위
