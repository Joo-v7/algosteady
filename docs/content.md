# 콘텐츠 규격

## 과제 구성

과제별 공통 설명과 언어별 코드·테스트를 분리한다. 사용자는 핵심 함수를 구현하고 입력 처리·테스트 호출은 사이트가 담당한다.

```text
content/<과제-id>/
├── exercise.json
└── <언어>/
    ├── starter.*
    ├── reference.*
    ├── harness.*
    └── tests.json
```

| 파일 | 역할 |
| --- | --- |
| `exercise.json` | 과제 설명, 학습 내용, 구현 규격, 채점 기준, 언어별 파일 연결 |
| `starter.*` | 사용자에게 제공하는 타입·함수 선언 등 시작 코드 |
| `reference.*` | 규격에 맞는 기준 구현 |
| `harness.*` | 테스트 입력 해석·사용자 함수 호출·결과 출력 |
| `tests.json` | 입력·기대 결과·채점 기준 연결·공개 여부 |

언어별 파일 경로는 `exercise.json`의 `languages`에서 지정한다. 개별 과제의 원본은 [학습 목록](curriculum.md)의 링크에서 확인한다.

## 과제 추가 절차

1. [학습 목록](curriculum.md)에서 구현할 항목을 선택하고 함수·상태·오류 동작을 정한다.
2. 과제 폴더에 설명·시작 코드·기준 코드·호출 코드·테스트를 작성한다.
3. 아래 기준으로 필요한 코드만 수정하고, 기준 구현과 대표 오답을 검증한다.
4. 학습·실습·실행·제출·기록 조회를 확인한 뒤 학습 목록의 항목을 체크하고 콘텐츠 링크를 연결한다.

| 작업 | 적용 기준 |
| --- | --- |
| 콘텐츠 5개 추가 | 새로운 과제마다 작성 |
| 화면·타입·CSS 수정 | 기존 표현으로 개념과 동작을 설명할 수 없는 경우 |
| 백엔드 운영 코드 수정 | 기존 등록·실행·채점 구조로 처리할 수 없는 경우 |
| 테스트 보완 | 등록·공개 범위·실제 실행·대표 오답·저장 흐름 중 변경 영향을 받는 동작 검증 |
| 문서 갱신 | 학습 목록의 항목·완료 상태 갱신. API나 공통 규격이 바뀌면 해당 문서 수정 |

테스트 참고 위치는 [콘텐츠 등록·조회](../backend/src/test/java/com/algosteady/exercise/ExerciseContentTests.java), [API·PostgreSQL 저장](../backend/src/test/java/com/algosteady/judging/JudgingApiPostgresTests.java), [Docker 실제 실행](../backend/src/test/java/com/algosteady/judging/runner/service/CodeExecutionDockerTests.java)이다. 과제마다 이 세 파일을 모두 수정하는 규칙은 아니며, 변경 영향에 맞춰 선택한다.

공통 테스트 대상·버전·개수는 [ExerciseContentSource](../backend/src/test/java/com/algosteady/support/ExerciseContentSource.java)가 콘텐츠 파일에서 읽는다. 새 과제를 추가할 때 전체 목록을 수정하지 않으며, 과제별 오답·특수 동작 검증이 필요한 경우에만 테스트를 보완한다.

## 메타데이터

| 항목 | 내용 |
| --- | --- |
| `id`, `version` | 과제 ID와 콘텐츠 버전 |
| `title`, `description`, `category`, `kind` | 제목·설명·분류·유형 |
| `learning` | 개념·구조·연산 과정 |
| `contract` | 타입·함수 규격·정상 및 오류 동작 |
| `prerequisites` | 선행 과제 ID |
| `criteria` | 채점 기준 ID·제목·설명 |
| `languages` | 언어별 표준·시작 코드·기준 코드·호출 코드·테스트 경로 |

공통 최상위 항목을 유지하고, `learning`에는 학습 내용과 시각화에 필요한 상태를, `contract`에는 구현할 함수와 동작 규격을 담는다. 구체적인 함수명·상태 필드·수치와 의미는 각 과제의 원본에서 관리한다. 세부 항목은 모든 과제에 공통으로 요구하지 않는다.

새로운 상태나 표현이 필요하면 해당 콘텐츠와 화면 타입·표시 로직을 함께 맞춘다. 콘텐츠에 필드를 추가하는 것만으로 새로운 시각화가 자동 지원되지는 않는다. 이 문서는 공통 파일 구성·등록·검증 규칙이 바뀔 때 수정한다.

## 테스트

| 항목 | 내용 |
| --- | --- |
| `id`, `criterionId` | 테스트 ID와 연결된 채점 기준 ID |
| `public` | 공개 예시 여부 |
| `description`, `input` | 검사 목적과 표준 입력 |
| `expected.stdout` | 기대 표준 출력 |
| `expected.exitCode` | 기대 종료 코드 |
| `expected.stderrRequired` | 오류 출력 필요 여부 |

- 각 기준에 테스트를 연결하고, 연결된 모든 테스트가 통과해야 기준을 통과 처리한다.
- 정상 동작·경계·오류·반복 사용을 검사하고, 기준 구현과 대표 오답으로 검증한다.
- 출력의 줄바꿈 형식을 정규화하고 마지막 줄바꿈 한 개의 유무를 제외해 비교한다. 종료 코드와 오류 출력 여부도 비교한다.
- 공개 예시 실행과 전체 채점을 구분한다. 과제 상세에는 기준 코드·호출 코드·비공개 테스트를 포함하지 않는다.

## 등록·버전 관리

콘텐츠는 Maven 리소스로 포함하며 서버 시작 시 검증 후 DB에 스냅샷으로 등록한다. 파일 경로는 과제 폴더 기준 상대 경로를 사용한다.

등록된 같은 버전은 덮어쓰지 않는다. 설명·코드·테스트를 변경하면 버전을 올리고, 기존 제출은 평가 당시 버전을 유지한다. 호출 코드는 실행부가 정한 사용자 소스 파일을 연결한다.
