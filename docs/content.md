# 콘텐츠 규격

## 구성 원칙

자료구조와 기본 알고리즘을 구현하는 훈련 항목을 구성한다.

- 자료구조는 구조와 기본 연산 전체를 하나의 과제로 구성한다.
- 알고리즘은 알고리즘별 함수 또는 필요한 함수 묶음을 하나의 과제로 구성한다.
- 기본 구현과 활용 과제를 구분하고 선행 학습 항목을 연결한다.
- 같은 알고리즘은 하나의 과제로 관리한다.
- 사용자는 핵심 구현을 작성하고 입력 처리와 테스트 호출은 사이트가 담당한다.
- 학습 탭에서 원리와 구현을 확인하고 구현 훈련 탭에서 직접 작성한다. 반복 훈련은 학습 탭을 거치지 않고 시작할 수 있다.
- 변수명과 작성 스타일은 자유롭게 사용하되 제공 타입, 함수 규격과 동작 계약을 준수한다.

## 디렉터리

```text
content/
├── stack-array/
│   ├── exercise.json
│   └── c/
│       ├── starter.c
│       ├── reference.c
│       ├── harness.c
│       └── tests.json
├── queue-linear/
│   ├── exercise.json
│   └── c/
├── queue-circular/
│   ├── exercise.json
│   └── c/
└── list-singly-linked/
    ├── exercise.json
    └── c/
```

과제 ID는 구현 방식까지 구분하는 소문자와 하이픈 이름을 사용한다.

## 파일 역할

| 파일 | 책임 |
| --- | --- |
| `exercise.json` | 공통 설명, 학습 내용, 동작 계약, 선행 과제, 기준과 언어별 파일 연결 |
| `c/starter.c` | 사용자가 처음 받는 헤더, 상수, 타입과 함수 선언 |
| `c/reference.c` | 규격을 충족하는 기준 구현 |
| `c/harness.c` | 입력 해석, 제출 함수 호출, 비교할 결과 출력 |
| `c/tests.json` | 테스트 입력, 기대 출력과 종료, 기준 연결, 공개 여부 |

과제 하나의 파일 묶음으로 설명, 편집, 실행과 채점을 구성한다. 공통 정보는 과제 루트에, 언어에 따라 다른 코드는 언어 폴더에 둔다.

백엔드의 exercise가 콘텐츠를 검증하고 버전별로 제공한다. judging은 요청된 버전의 호출 코드, 기준과 테스트로 판정한다. judging.runner에는 코드와 테스트 입력을 전달하고 기대값 비교는 judging의 채점 서비스에서 수행한다. 실행 이미지와 명령은 서버 실행 설정과 언어 정의에서 관리하며 콘텐츠 파일에서 실행 명령을 받지 않는다.

## 과제 메타데이터

`exercise.json`은 다음 정보를 갖는다.

| 필드 | 내용 |
| --- | --- |
| `id` | 과제 고유 ID |
| `version` | 콘텐츠 버전 |
| `title` | 표시 제목 |
| `category` | 스택, 큐, 정렬 등 분류 |
| `kind` | 자료구조, 알고리즘, 활용 |
| `description` | 개념 설명 2~3문장 |
| `learning` | 개념, 구조 설명, 연산 과정과 단계별 예시 |
| `contract` | 구현 범위, 입력, 반환값, 오류와 구현 방식 |
| `prerequisites` | 선행 과제 ID 목록 |
| `criteria` | 기준 ID, 표시 순서, 제목과 설명 |
| `languages` | 언어별 코드 설명, 시작 코드, 기준 코드, 호출 코드와 테스트 파일 경로 |

파일 경로는 과제 폴더를 기준으로 기록한다. 서버의 절대 경로나 개발자 PC 경로를 저장하지 않는다. 공개 예시는 공개 테스트의 입력과 기대 결과로 구성한다.

## 학습 콘텐츠

학습 탭은 개념, 구조, 연산 과정, 구현 코드 순서로 구성한다. 공통 원리와 상태 변화는 `exercise.json`의 `learning`에 기록하고 언어별 코드 설명은 `languages`에 기록한다.

배열 스택은 LIFO, `data`와 `top`의 의미, 빈 상태와 포화 상태, push와 pop 전후의 변화, peek가 상태를 유지하는 이유를 설명한다. 그다음 구조체와 각 함수의 코드를 설명과 함께 표시한다.

함수 구현은 사용자가 펼쳤을 때 제공한다. 학습 코드와 훈련의 기준 코드는 같은 `reference.c`를 사용해 동작이 어긋나지 않도록 한다.

## 시작 코드와 기준 구현

시작 코드는 필요한 헤더, 상수, 자료형과 함수 선언을 제공한다. 사용자는 지정된 함수의 정의와 본문 전체를 직접 작성한다. 부분적으로 구현된 함수 본문이나 정답 로직의 빈칸은 제공하지 않는다. 입력 처리와 `main()`은 사이트가 제공한다.

기준 구현은 과제의 구현 규격과 동작 계약을 충족해야 한다. 학습 탭에서 완성된 함수 구현을 펼치거나 구현 훈련 탭에서 `기준 코드 보기`를 누르면 해당 훈련 회차에 열람 여부를 기록한다. 선언과 개념 설명만 본 경우에는 기록하지 않는다.

컴파일할 때 제출 파일을 작업 공간의 `submission.c`로 저장한다. `harness.c`는 이를 포함하고 테스트용 `main()`을 제공한다. 사용자 코드와 호출 코드는 C17로 함께 컴파일한다. 입력 해석 방식은 과제의 호출 코드가 담당하며 구현 규격과 함께 문서화한다.

## 테스트 규격

`tests.json`은 다음 필드를 가진 테스트 목록이다.

| 필드 | 내용 |
| --- | --- |
| `id` | 과제 안에서 고유한 테스트 ID |
| `criterionId` | 연결할 채점 기준 ID |
| `public` | 공개 예시 여부 |
| `description` | 검사 목적 |
| `input` | 호출 프로그램에 전달할 표준 입력 |
| `expected.stdout` | 기대 표준 출력 |
| `expected.exitCode` | 기대 종료 코드 |
| `expected.stderrRequired` | 오류 출력이 필요한지 여부 |

표준 출력은 줄바꿈을 정규화하고 마지막 줄바꿈의 유무를 제외한 내용을 비교한다. 오류 문구 일치를 요구하는 과제는 해당 조건을 규격에 별도로 명시한다. 테스트 입력은 `harness.c`가 읽을 수 있는 형식으로 작성한다.

테스트마다 프로그램을 새로 실행한다. 빈 입력, 단일 요소, 일반 입력, 경계와 반복 사용을 포함한다. 자료구조는 여러 인스턴스의 독립성을 함께 확인한다.

## 채점 기준

각 기준은 실제 테스트에 연결한다. 한 기준의 모든 테스트가 통과해야 통과 상태가 된다.

| 상태 | 화면 표시 |
| --- | --- |
| 대기 | 회색 빈 원 |
| 판정 중 | 회전 표시와 확인 중 |
| 통과 | 초록색 체크와 통과 |
| 실패 | 빨간색 실패 표시와 실패 |
| 검사 불가 | 회색 표시와 원인 |

실패한 기준을 선택하면 입력, 기대값, 실제값과 오류를 보여준다. 컴파일 실패는 기능 기준의 실패와 구분한다. 종료를 기대하는 테스트는 종료 코드와 오류 출력으로 판정하고 일반 런타임 오류로 처리하지 않는다.

동작 테스트 통과는 코드 스타일, 시간 복잡도나 내부 구현 방식까지 보증하지 않는다. 배열 사용, 재귀 사용, 내장 자료구조 및 정렬 함수 사용 제한은 규격에 명시하고 실제 자동 검사 범위를 함께 표시한다.

## 첫 과제: 고정 배열 스택

| 항목 | 규격 |
| --- | --- |
| ID | `stack-array` |
| 값 타입 | `typedef int element` |
| 용량 | `MAX_STACK_SIZE` 100 |
| 구조체 | `StackType`, `data` 배열과 `top` |
| 초기 상태 | `top == -1` |
| 상태 함수 | 참 1, 거짓 0 |

### 시작 코드

헤더, 상수, typedef와 구조체는 제공하고 아래 함수 선언에 맞춰 구현한다.

```c
#include <stdio.h>
#include <stdlib.h>

#define MAX_STACK_SIZE 100

typedef int element;

typedef struct {
    element data[MAX_STACK_SIZE];
    int top;
} StackType;

void init_stack(StackType *s);
int is_empty(StackType *s);
int is_full(StackType *s);
void push(StackType *s, element item);
element pop(StackType *s);
element peek(StackType *s);
```

사용자는 이 코드 아래에 6개 함수의 정의를 작성한다. 구조체와 함수 이름, 인자 및 반환 타입은 호출 규격으로 유지한다.

### 동작 계약

- `init_stack`: 스택을 빈 상태로 초기화한다. 배열 전체를 0으로 채울 필요는 없다.
- `is_empty`: 빈 상태인지 반환하고 스택을 변경하지 않는다.
- `is_full`: 100개가 저장된 포화 상태인지 반환하고 스택을 변경하지 않는다.
- `push`: 맨 위에 값을 추가한다. 포화 상태에서는 `stderr`에 오류를 알리고 기존 상태를 유지한 채 반환한다.
- `pop`: 맨 위 값을 반환하고 제거한다. 빈 상태에서는 오류를 출력하고 `exit(1)`로 종료한다.
- `peek`: 맨 위 값을 반환하고 유지한다. 빈 상태에서는 오류를 출력하고 `exit(1)`로 종료한다.

정상 연산은 오류를 출력하지 않는다. 오류 메시지의 문구는 정확히 일치할 필요가 없다. 테스트에는 유효한 구조체 포인터를 전달한다.

### 공개 예시

```text
초기화
push(10)
push(20)
peek()       → 20
pop()        → 20
pop()        → 10
is_empty()   → 1
```

### 기준별 검사

| 기준 | 검사 내용 |
| --- | --- |
| 초기화 | 생성과 재초기화 후 빈 상태 |
| 삽입 | 값과 top의 변경 |
| LIFO 삭제 | 역순 반환과 모두 삭제한 뒤 빈 상태 |
| 조회 | 반복 조회 후 값과 top 유지 |
| 빈 스택 | pop과 peek의 종료 코드 1, 오류 출력 |
| 포화 상태 | 100개 저장, 추가 삽입 거부, 기존 값 유지 |
| 경계와 재사용 | 포화 후 삭제 및 재삽입, 반복 삽입과 삭제 |
| 스택 독립성 | 두 스택을 교차 조작해도 상태가 독립적 |

고정 배열을 가진 스택 구조체를 동적 할당하는 방식과 배열 용량을 늘리는 동적 배열 스택은 구분한다.

## 콘텐츠 버전

과제 ID는 유지하고 규격, 테스트 또는 기준 구현이 바뀌면 버전을 변경한다. 표시 문구 수정과 동작 계약 변경을 구분해 변경 내용을 기록한다.

제출에는 평가 당시 콘텐츠 버전을 저장한다. 과거 버전의 콘텐츠와 테스트를 보존하고 기존 제출 결과를 새 버전의 결과로 덮어쓰지 않는다. 최신 버전의 과제로 실행 및 채점할 때 요청한 버전과 서버의 제공 버전이 일치하는지 확인한다.

## 콘텐츠 등록과 검증

1. 과제의 구현 주제와 동작을 정의한다.
2. 설명, 규격, 시작 코드, 기준 구현과 테스트를 작성한다.
3. 필수 필드, 파일 존재, 과제 및 기준 ID, 테스트 연결을 검증한다.
4. 기준 구현이 전체 테스트를 통과하는지 확인한다.
5. 의도적인 오답에서 관련 기준이 실패하는지 확인한다.
6. 검증된 콘텐츠와 버전을 DB에 등록한다.

자료구조별 오류 처리는 해당 과제의 계약으로 기록한다. 모든 과제에 같은 종료 방식이나 반환 규칙을 적용하지 않는다.
