# 콘텐츠 규격

## 과제 구성

과제별 공통 설명과 언어별 코드·테스트를 분리한다. 사용자는 핵심 함수를 구현하고 입력 처리·테스트 호출은 사이트가 담당한다.

```text
content/<과제-id>/
├── exercise.json
└── <언어>/
    ├── starter.*
    ├── reference.*
    ├── harness.*
    └── tests.json
```

| 파일 | 역할 |
| --- | --- |
| `exercise.json` | 과제 설명, 학습 내용, 구현 규격, 채점 기준, 언어별 파일 연결 |
| `starter.*` | 사용자에게 제공하는 타입·함수 선언 등 시작 코드 |
| `reference.*` | 규격에 맞는 기준 구현 |
| `harness.*` | 테스트 입력 해석·사용자 함수 호출·결과 출력 |
| `tests.json` | 입력·기대 결과·채점 기준 연결·공개 여부 |

실제 예시는 [배열 스택 콘텐츠](../content/stack-array)를 참고한다. 언어별 파일 경로는 `exercise.json`의 `languages`에서 지정한다.

## 메타데이터

| 항목 | 내용 |
| --- | --- |
| `id`, `version` | 과제 ID와 콘텐츠 버전 |
| `title`, `description`, `category`, `kind` | 제목·설명·분류·유형 |
| `learning` | 개념·구조·연산 과정 |
| `contract` | 타입·함수 규격·정상 및 오류 동작 |
| `prerequisites` | 선행 과제 ID |
| `criteria` | 채점 기준 ID·제목·설명 |
| `languages` | 언어별 표준·시작 코드·기준 코드·호출 코드·테스트 경로 |

## 테스트

| 항목 | 내용 |
| --- | --- |
| `id`, `criterionId` | 테스트 ID와 연결된 채점 기준 ID |
| `public` | 공개 예시 여부 |
| `description`, `input` | 검사 목적과 표준 입력 |
| `expected.stdout` | 기대 표준 출력 |
| `expected.exitCode` | 기대 종료 코드 |
| `expected.stderrRequired` | 오류 출력 필요 여부 |

- 각 기준에 테스트를 연결하고, 연결된 모든 테스트가 통과해야 기준을 통과 처리한다.
- 정상 동작·경계·오류·반복 사용을 검사하고, 기준 구현과 대표 오답으로 검증한다.
- 출력의 줄바꿈 형식을 정규화하고 마지막 줄바꿈 한 개의 유무를 제외해 비교한다. 종료 코드와 오류 출력 여부도 비교한다.
- 공개 예시 실행과 전체 채점을 구분한다. 과제 상세에는 기준 코드·호출 코드·비공개 테스트를 포함하지 않는다.

## 등록·버전 관리

콘텐츠는 Maven 리소스로 포함하며 서버 시작 시 검증 후 DB에 스냅샷으로 등록한다. 파일 경로는 과제 폴더 기준 상대 경로를 사용한다.

등록된 같은 버전은 덮어쓰지 않는다. 설명·코드·테스트를 변경하면 버전을 올리고, 기존 제출은 평가 당시 버전을 유지한다. C 호출 코드는 사용자 코드인 `submission.c`를 포함한다.
