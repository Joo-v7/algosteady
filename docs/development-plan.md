# 개발 계획

## 목표

자료구조와 기본 알고리즘을 C로 직접 구현하고, 실행, 항목별 채점, 수정과 기록 확인을 반복할 수 있는 웹을 완성한다. C의 훈련 기능과 콘텐츠를 완성한 뒤 다른 언어를 추가한다.

## 개발 범위

| 구분 | 범위 |
| --- | --- |
| 사용 환경 | PC 웹 브라우저, 개인 로컬 실행 |
| 훈련 | 자료구조의 구조와 연산 전체, 알고리즘 함수 구현 |
| 학습 | 개념, 구조, 연산 과정, 함수별 구현 코드와 설명 |
| 실행 | C17 컴파일, 공개 예시 실행 |
| 평가 | 테스트 기반 기준별 판정과 실패 상세 |
| 저장 | 초안, 제출 코드, 결과, 작성 및 실행 시간, 기준 코드 열람 |
| 콘텐츠 | 분류별 기본 구현과 활용 과제 |
| 확장 | C 완료 후 Java, Python, C++ |
| 배포 | 로컬 완성 후 서버 배포와 자동화 |

## 개발 순서

백엔드는 exercise, training, judging, common으로 구성한다. 의존 방향은 `training → judging → exercise`다. training은 훈련 및 제출 원본을, judging은 작업 상태와 결과를 소유한다. 제출 기록 조회는 두 기능의 조회 결과를 조합하며 채점부가 제출 원본을 갱신하지 않는다.

| 단계 | 산출물 | 완료 기준 |
| --- | --- | --- |
| 개발 환경 | React, Spring Boot, DB, 프록시 | 브라우저에서 API 호출, DB 연결, 빌드 성공 |
| 배열 스택 콘텐츠 | 학습 내용, 규격, 시작 코드, 기준 구현, 호출 코드, 테스트 | 학습과 기준 코드 일치, 기준 구현 전체 통과, 대표 오답 실패 |
| 공통 실행부와 C 환경 | 언어 정의, 실행 세션, Docker 이미지, 제한 및 정리 | C 정상 실행과 오류 구분, 테스트 완료 결과 전달 |
| API 및 저장 | 콘텐츠, 초안, 제출, 작업, 결과 API와 DB | 실행 및 채점 결과 저장과 재조회 |

| 기록과 재훈련 | 자동 저장, 타이머, 기준 코드, 제출 기록 | 재시작 복구와 이전 제출 불러오기 |
| 과제 유형 확대 | 원형 큐, 연결 리스트, 탐색, 정렬 | 서로 다른 구현과 입력 형식 지원 |
| C 콘텐츠 완성 | 자료구조와 기본 알고리즘의 C 과제 | 전체 기준 구현과 대표 오답 검증 |
| 언어 확장 | Java, Python, C++ 실행 및 콘텐츠 | 언어별 동일 동작 계약 검증 |
| 서버 배포 | 패키징, CI/CD, 운영 실행 안내 | main 병합 후 검증과 배포 |

환경 구성 이후의 첫 기능 단위는 고정 배열 스택이다. 모든 콘텐츠를 먼저 작성한 뒤 화면을 만드는 방식 대신, 배열 스택 하나에서 구현, 실행, 채점과 기록 흐름을 완성하고 나머지 항목을 확대한다.

## 첫 기능: 배열 스택

### 콘텐츠

- 고정 배열 스택의 구조체와 6개 연산을 제공한다.
- 개념, 구조, 연산별 상태 변화와 코드 설명을 작성한다.
- 시작 코드는 헤더, 상수, 타입과 함수 선언만 제공하고 함수 정의 전체를 직접 작성하게 한다.
- 초기 상태, 삽입, LIFO 삭제, 조회, 빈 상태, 포화 상태, 재사용과 독립성을 검사한다.
- 공개 예시와 전체 테스트를 구분한다.
- 기준 코드와 의도적인 오답으로 채점 기준을 검증한다.

### 실행 환경

- judging.runner에 공통 실행 서비스, 언어 정의, 설정, 실행 모델과 Docker 실행부를 둔다.
- 실행 명령과 파일명은 Java, 이미지와 제한은 properties에서 관리한다.
- 컨테이너 하나에서 한 번 준비하고 테스트마다 새 프로세스로 실행한다.
- 제출 코드와 테스트 호출 코드를 컴파일한다.
- stdout, stderr, 종료 코드와 실행 시간을 수집한다.
- 빈 pop과 peek의 정상적인 오류 종료를 별도 테스트로 검사한다.
- 무한 루프, 비정상 종료, 출력 초과를 구분한다.
- 제한 도달 시 실행을 종료하고 작업 공간을 정리한다.
- 테스트 완료 콜백으로 결과를 전달한다. 실행부는 채점 기준과 DB를 참조하지 않는다.

### API와 데이터

- 콘텐츠 파일을 검증하고 버전별로 등록한다.
- 공개 예시 실행과 제출 채점을 분리한다.
- 단일 작업 큐로 실행하고 기준별 결과를 저장한다.
- Flyway로 테이블을 만들고 JPA로 저장 및 조회한다.
- 제출 코드와 콘텐츠 버전은 제출 이후 변경하지 않는다.
- training의 제출에는 작업 ID를 연결하고 상태와 결과는 judging에서만 저장한다.
- 제출 및 작업 등록을 같은 트랜잭션으로 처리하고 커밋 이후 작업을 실행한다.
- judging은 전달받은 코드와 exercise의 해당 버전 콘텐츠를 사용하며 training을 참조하지 않는다.
- 기록 조회 시 training은 judging의 조회 서비스를 사용해 제출 원본과 결과를 합쳐 반환한다.

### 화면과 기록

- 과제에 학습 탭과 구현 훈련 탭을 제공한다.
- 학습 탭은 개념과 연산 과정을 먼저 표시하고 함수 구현은 펼쳐서 볼 수 있게 한다.
- 학습을 거치지 않고 구현 훈련으로 바로 진입할 수 있다.
- Monaco에 시작 코드를 표시한다.
- 실행 결과와 컴파일 오류를 확인할 수 있다.
- 채점 기준의 대기, 판정 중, 통과, 실패, 검사 불가를 표시한다.
- 실패 기준을 선택하면 실제 테스트 상세를 보여준다.
- 코드 수정 후 이전 결과임을 표시하고 재채점 시 상태를 초기화한다.
- 새로고침과 서버 재시작 후 초안과 제출 기록을 복구한다.
- 탭 전환 시 작성 코드와 해당 회차의 열람 기록을 유지한다.

## 작성 및 실행 시간

작성 시간은 훈련 회차의 첫 입력부터 누적한다. 화면 이탈이나 명시적인 일시 정지 시 멈추며 초안 저장과 제출 시점에 누적 시간을 기록한다. 재훈련은 기록을 보존하면서 새 회차와 시간을 시작한다.

실행 시간은 테스트 프로그램 시작부터 종료까지 측정한다. 컨테이너 준비와 컴파일 시간은 제외한다. 실행 시간은 학습 참고값이며 언어별 순위를 제공하지 않는다.

현재 측정에는 컨테이너 내부 실행 관리 명령의 오버헤드가 포함된다. 정밀 측정 개선은 별도 변경으로 검증한다.

과제 진입 시 현재 훈련 회차를 생성하거나 복구한다. 학습 중 완성된 함수 구현을 보거나 기준 코드를 열람하면 해당 회차의 열람 여부를 저장하고 이후 제출에도 포함한다. 학습 내용을 읽는 시간은 작성 시간에 포함하지 않는다. 채점할 때마다 새 제출을 저장한다.

## C 콘텐츠 개발 순서

배열 스택 다음에 원형 큐, 단순 연결 리스트, 이진 탐색, 삽입 정렬을 구현해 인덱스 순환, 동적 메모리, 반환값과 배열 변경을 검증한다. 이후 분류별로 전체 범위를 확대한다.

| 분류 | 개발 항목 |
| --- | --- |
| 자료구조와 알고리즘 | 추상 자료형, 동작 계약, 복잡도 설명 |
| 순환 | 거듭제곱, 피보나치, 하노이탑 |
| 배열, 구조체, 포인터 | 기초 설명, 다항식 연산, 희소행렬 |
| 스택 | 고정 배열 스택, 동적 배열 스택, 괄호 검사, 후위 표기 수식 계산, 미로 |
| 큐 | 선형 큐, 원형 큐, 덱, 버퍼와 시뮬레이션 활용 |
| 리스트 | 배열 리스트, 단순, 원형 및 이중 연결 리스트, 리스트 다항식, 연결 스택과 큐 |
| 트리 | 이진 트리 표현, 재귀 및 반복 순회, 레벨 순회, 추가 연산, 스레드 트리, 이진 탐색 트리 |
| 우선순위 큐 | 히프, 히프 정렬, 스케줄링, 허프만 코드 |
| 그래프 | 인접 행렬 및 인접 리스트 표현, DFS, BFS, Kruskal, Prim, Dijkstra, Floyd, 위상 정렬 |
| 정렬 | 선택, 삽입, 버블, 셸, 합병, 퀵, 히프, 기수 |
| 탐색 | 순차 탐색, 이진 탐색, AVL, 2-3, 2-3-4 트리 |
| 해싱 | 해시 함수, 개방 주소법, 체이닝 |

각 분류는 과제 규격 작성, 기준 구현, 테스트, 사이트 연결 순서로 개발한다. 설명 중심 항목은 학습 자료로 제공하고, 구현 가능한 항목은 독립 과제로 구성한다. 같은 구현은 중복 등록하지 않는다.

기본 구현을 먼저 개발하고 활용 과제를 연결한다. 언어별 시작 코드의 수를 늘리는 것보다 C 과제의 채점 정확성과 반복 훈련 흐름을 우선한다.

## 품질 기준

### 콘텐츠

- 모든 기준 구현이 해당 콘텐츠 버전의 전체 테스트를 통과한다.
- 학습 코드와 기준 구현이 일치하고 시작 코드에는 정답 구현을 포함하지 않는다.
- 대표 오답에서 의도한 기준이 실패한다.
- 빈 상태, 단일 요소, 용량 경계, 반복 사용을 검사한다.
- 테스트하지 않는 조건을 자동 통과로 표시하지 않는다.

### 실행 및 판정

- 컴파일 실패, 정상 실행, 오답, 런타임 오류, 시간 초과, 출력 초과와 환경 장애를 구분한다.
- 한 테스트가 실패해도 독립적인 나머지 기준을 검사한다.
- 실행 제한과 임시 공간 정리를 실제 컨테이너에서 확인한다.
- 기준별 결과는 실제 판정 완료 순서로 갱신한다.
- 제한에 걸린 테스트 이후에도 독립적인 다음 테스트를 실행한다.
- 테스트 완료 콜백의 순서와 중단·장애 시 작업 공간 정리를 검증한다.
- judging에서 training으로 향하는 의존과 실행부의 DB 접근이 없는지 확인한다.

### 실행부 검증 명령

Java 21 환경에서 backend 디렉터리로 이동해 실행한다. DB 없이 실행부와 설정 연결을 검증한다. Docker 검증은 기본적으로 제외된다.

```bash
cd backend
./mvnw '-Dtest=CodeExecution*Tests,ProcessExecutorTests,DockerContainerManagerTests,RunnerPropertiesTests' test
```

Docker Desktop 또는 Docker 엔진을 실행하고 `algosteady-runner-c:14.4.0` 이미지를 준비한 뒤 실제 실행 검증을 포함한다.

```bash
./mvnw '-Dtest=CodeExecution*Tests,ProcessExecutorTests,DockerContainerManagerTests,RunnerPropertiesTests' -Dalgosteady.docker.tests=true test
```

실제 실행 검증은 스택 22개 테스트, 컴파일 실패, 시간·출력 제한, 다음 테스트 실행, 종료 정보와 작업 정리를 확인한다. 실행부 검증 명령은 전체 애플리케이션의 DB 통합 테스트를 포함하지 않는다.

### 저장 및 화면

- 코드 수정과 재제출 후 이전 결과를 새 코드의 결과로 표시하지 않는다.
- 초안, 제출과 기준 코드 열람 여부를 복구한다.
- 학습 탭의 구현 코드 열람도 같은 회차의 열람 기록에 반영한다.
- 기록된 시간은 정의된 측정 범위와 일치한다.
- 이전 제출 코드를 불러와도 과거 제출 원본을 변경하지 않는다.
- 채점 상태와 결과를 제출 테이블에 중복 저장하지 않는다.

### 배포

- Java 및 Node 버전과 실행 이미지 버전을 관리한다.
- CI에서 프런트 빌드 및 lint, 백엔드 테스트를 수행한다.
- 배포 전에 기준 구현과 실행 제한 검증을 통과한다.
- 실제 비밀번호, 키와 개인 IDE 설정을 저장소에 포함하지 않는다.

## C 버전 완료 기준

분류별 개발 항목이 설명, 구현 규격, 시작 코드, 기준 구현과 테스트를 갖추고 웹에서 실행 및 채점할 수 있어야 한다. 초안 저장, 제출 기록, 재훈련과 오류 표시가 전체 항목에 동일하게 동작해야 한다.

C 버전 완료 후 동일 과제의 동작 계약을 유지하면서 Java, Python, C++를 추가한다. 언어별 문법, 메모리 관리, 오류 표현과 런타임 차이는 해당 언어의 구현 규격에 반영한다.
